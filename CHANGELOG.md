# twidget (Nanogram fork) changelog

Branch `nanogram`. Base: Telegram's 4769d72. Newest first.

## Unreleased

- **Fixes for the iOS widget tests after the 13.2 merge** (iOS WidgetRuntime's first run against this fork; regression test `tests/litehtml_tests.cpp`, ctest `twidget_litehtml`):
  - Collapsed table borders are now opt-in: `document_container::paint_collapsed_borders_over_cells()` (default false, upstream's painting: each cell draws its own borders in its own paint, the table its own). `apple/` `LHContainer` and `core/` opt in and keep the fork's behaviour (conflict resolution, borders after the cells). The fork's table pass drew the borders outside any visited paint, so iOS WidgetRuntime's layer mirror saw stray draws, stopped every widget with a `border-collapse: collapse` table ("Widget core error", `render-internal`) and lost the cell borders of the rest.
  - An unresolved `var()` (no such property and no fallback, a cycle, bad syntax) makes the declaration unset again (Telegram edit 57): `subst_vars_` ignored `resolve_vars`'s result, so the tokens stayed, the declaration was dropped and an earlier one (`flex-grow:3; flex:var(--nope)`) stood.
  - `dir=auto` is a presentational hint: a `direction` declared for the element itself wins (iOS WidgetRuntime resolves dir=auto from its DOM and declares it through `[data-tg-dir]`), and the first-strong walk skips bdi, script, style, textarea and elements with a dir of their own, as HTML's auto directionality does.
  - The bidi fallback is opt-in: `document_container::reorder_bidi_by_first_strong_character()` (default false). Since the 13.2 merge `line_box::reorder_bidi` ran the fork's first-strong-character reordering for every host whose `bidi_levels` gave no levels, so with upstream's default hook a `direction: rtl` line of two inline-blocks came out mirrored (iOS `TwidgetForkTests` fork_test.cpp:358, "the default hook keeps the logical order"). Without levels the order is now logical, as upstream's; `apple/` `LHContainer` and `core/` opt in and keep the reordering they had before the merge; iOS WidgetRuntime answers `bidi_levels` itself and is unaffected. Regression test `testBidiFallbackFollowsTheHostsChoice`.
  - `apple/` `LHContainer::draw_box_shadow`: under `LH_EXACT_SHADOWS` a shadow whose raster the cache cannot hold (a turned or skewed CTM) was drawn through a second, differently laid out low-resolution raster (the fork's pre-edit-65 `|down` fallback) instead of at full resolution, so the "exact" reference of a turned shadow was itself approximate and 11 levels from the edit-65 raster at 3x (iOS `TwidgetRenderingTests` `testBlurredShadowsStayCloseToTheExactOnes`, limit 8; the same 11 before the merge). Without `LH_EXACT_SHADOWS` that fallback never drew (a blur past 24 device pixels takes the edit-65 branch and `DrawDownsampled` declines smaller ones), so it is removed and production output does not change; the turned shadow is now 2 levels from the exact one. The test is added to `apple/Tests` `ShadowRasterTests`.
  - A patch's style bytes equal a rebuild's again (edit 21): `document::commit_patch` no longer restyles an element the session matched again (the environment's reach, an attribute change) and then removed or moved, itself or with an ancestor. Its charges went back when it left the tree, but the restyle spliced its `var()`s again (the fork's `subst_vars` keeps a shorthand's `var()` tokens, so every compute splices them; out of the tree a `var()` takes its fallback) and those bytes stayed charged, held by nothing: iOS WidgetRuntime `testRandomEditsMatchARebuild` saw 16808 style bytes against a rebuild's 14520 after a reduced-motion change, two removals and a move (one detached `<button>`'s background, font, padding and border-radius fallbacks, 2288). Regression test `testAPatchKeepsTheStyleBytesOfAFreshBuild`.
  - The style-pass replay (edit 84) starts the text-piece cap's flag where a build's style pass starts it: set when the document's own text was cut by the parse or the caller's walk (recorded at finalize), not cleared. A commit that replayed a document whose own text was cut, with generated content making no piece, left `text_limited()` false while a fresh build has it true (iOS `TwidgetExternalTests` external_test.cpp:793, `.x::before{content:attr (title)}`, which 13.2's parser read as `attr(title)` and the fork's, as CSS does, does not). Regression test `testAReplayKeepsTheParsesTextCut`.
  - `apple/` `LHContainer::draw_borders`: the per-side polygons have four corners but were drawn as five points, the fifth (0, 0), so in a rounded ring with one side of another colour the right side's polygon reached over the top side (26d60e6). Seen on iOS (`LayerTreePainterTests`) and present on the Mac.

- **litehtml merged with upstream Telegram-iOS 13.2** (their litehtml = Telegram twidget b5878f9 plus its VENDOR edits), three-way: OURS = this fork, BASE = b5878f9, THEIRS = 13.2 (the first attempt used the wrong base and was discarded). The struct layouts the iOS WidgetRuntime asserts are upstream's again (`css_length` 16, `vector_path` 168, `filter_function` 64, `paint_group` 52, `font_description` 168 bytes); the fork's extra data moved to hooks and side tables. Checked with `clang -fsyntax-only` only (litehtml 66/66, WidgetRuntime 121/121, iOS host tests 140/143 with the 3 failures from generated headers missing in this checkout, apple/ 10/10 for macOS and iOS, apple/Tests 44/44, core 10/10, tests/core_tests.cpp parses); no build, link or test run.
  - Came in from 13.2: `calc_node` (calc trees, `calc_ref`), `text-overflow: ellipsis` (render-item ellipsis, `ellipsis_bytes`), `object-fit` and `object-position`, individual `translate`/`rotate`/`scale`, CSS `initial`/`unset`/`revert`, `@layer` origins, `tabular_nums` in `font_description`, word-spacing added to space widths by litehtml, start/end text-align against the block's direction, the SVG painter and `<use>` budget, and VENDOR edits 1 to 91 as upstream has them (they are in the merged files).
  - Fork features kept: collapsed table borders, the `grid` shorthand, `has_viewport_units`, `render_out_of_flow`, `same_resolved_layout_input`, `get_wrapping`/`set_word_break`, `compute_opacity`/`compute_transform` and `patch_inline_properties` (macOS inline-patch fast path; it also reads the individual transforms), `max_var_substitution_tokens`, the bidi fallback (`strong_direction`), `style::add_length_property`, the border-clip and render-tree-rebuild repairs, gumbo, Mac template patching, per-element layout origins for partial repaint, and repeating-gradient limits.
  - Changed or moved to hooks: font features. `font_description` keeps only `tabular_nums`; the merged `font-variant-numeric` and `font-feature-settings` list (`tnum=1,zero=1`, validated at parse time as before) is kept in `css_properties::get_font_features()` and reaches the host through the new `document_container::create_font(descr, features, doc, fm)` (the default forwards to the old three-argument one); `document::get_font` caches by `descr.hash() + ":ff=" + features`. SVG stroke gradients: `document_container::draw_path_stroke_gradient` and a `begin_group(owner)` overload carry what `vector_path` and `paint_group` no longer can. Fork `css_wide_keyword`, `ua_property` and the calc engine are replaced by upstream's `initial`/`unset`/`revert` and `calc_node`; the fork's own text-overflow code was removed in favour of upstream's.
  - Consumers: apple/ and core/ read `tabular_nums`/features instead of `descr.features`, pass word-spacing 0 (litehtml spaces already carry it), use `css_length::is_calc()`, `text_may_hold_viewport_unit`, `ellipsis_bytes()`/`ellipsis_hidden()` for text runs, and the stroke-gradient hook; neither implements `bidi_levels`, so both use litehtml's fallback reordering.
  - Review fixes after the merge: bidi reordered twice per line; RTL alignment flipped twice; repeating-gradient guard (zero or tiny period hung) restored; the fallback reordering skipped `direction: rtl` lines (now mirrors across the line's own extent); `quotes` is a raw declaration again; `element::mark_layout_dirty` records the layout origin again; text runs after an ellipsis report no text; dead text-overflow, `m_layered` and `get_transform_fill_box` code and two `#if 0` merge artefacts removed.
  - word-spacing on preserved and no-break spaces (core): upstream widens only collapsible spaces, so under `white-space: pre`/`pre-wrap` and at U+00A0 inside a word the core renderer lost word-spacing (tests/core_tests.cpp "word-spacing widens each space as it paints"). New opt-in hooks `document_container::word_spacing_on_every_separator()` (default false) and `draw_spaced_text(..., word_spacing)` (default forwards to `draw_text`): when the host opts in, `el_text` widens every U+0020/U+00A0 in layout and hands the run's word-spacing at paint, and core's renderer splits the run at those spaces as before the merge. Hosts that do not opt in (iOS WidgetRuntime, apple/) keep upstream's behaviour; no struct changed.

- **SwiftPM**: `litehtml/no-public-headers/` now exists (with a README). Xcode 27's package resolver rejects a `publicHeadersPath` that is missing, which stopped the macOS app from resolving packages.

- Restore `style::add_length_property` (litehtml/src/style.cpp): the Apple-layer merge dropped its definition while the header and 11 callers kept it, so the Android link failed with an undefined symbol (first combined build, 2026-11-14). Every other litehtml definition matches the last working copy 653c029.
- Apple layer and litehtml (repair): dotted and dashed side borders clip to the side on iOS as well (the clip had moved under the macOS-only branch), and `document::apply_template_values` and `update_structure` rebuild the render tree again when the patch cannot keep it (the merge had dropped the macOS tail of `restyle_after_patch`; the iOS `commit_patch` path is unchanged).
- Apple layer and litehtml: the merge of the iOS app's edits now compiles for iOS and macOS (syntax-checked per file): imports and guards of Cocoa, the iOS and macOS dash metrics for dashed borders, iOS spellings of the font and rect API, and the splices the merge left in `document.cpp`.
- litehtml: UAX #9 bidi through the host (`document_container::bidi_levels`, rule L2) when the host answers; the simplified first-strong-character reordering remains the fallback.
- litehtml: the calc() registry holds 16,384 distinct expressions per process (was 4,096).
- litehtml and the Apple layer: the Nanogram iOS app's edits (VENDOR.md edits 1 to 91 there) are carried, so one litehtml serves the iOS, macOS and Android apps: an external-DOM builder and the master CSS in C++, patches in place (text, attributes, structure, pseudo-classes, counters, environment, sheets, document element), a style-byte budget, caps on nesting, lists, text pieces and pseudo-element content, a `<use>` instance budget, `:lang()` and `:empty` per Blink, getComputedStyle lookups, host profile hooks, iOS image policy and no-network counters. Features this branch already had (the macOS and Android versions of fill-box, calc, CSS-wide keywords, object-fit, text-overflow, direction and bidi, colour-stop fix-up, dash metrics, grid-template and others) stay as they were. See NANOGRAM-CHANGES.md for what is and is not carried.
- litehtml: a `<canvas>` takes its intrinsic size from its width and height attributes (default 300x150) and they no longer become CSS sizes, so a responsive canvas keeps its aspect ratio in the Swift renderer; the core renderer's `tw-canvas:` path still works.
- gumbo: parsing is linear in the input and bounded in memory (13 limits and fixes).
- Swift renderer: widget-sandbox v0.6.0 paint limits, content safe areas, host-enabled text selection, percentage image
  heights, exact `fill-box` extrema; new layout, canvas, safe-area and paint-policy tests; opt-in stress-kit runner.
